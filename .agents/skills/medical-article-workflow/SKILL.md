# Medical Article Workflow

Medical content lives under `webapp/content/docs/` as Markdown with YAML frontmatter. Git is the source of truth, and publishing must remain independent of the RAG backend.

## Load the applicable policy

Read only the canonical guidelines required by the task:

- Drafting or revising content: `webapp/content/docs/guidelines/author-guideline.md`
- Clinical review: `webapp/content/docs/guidelines/reviewer-guideline.md`
- Approval, publication, or workflow changes: `webapp/content/docs/guidelines/editor-guideline.md`

For existing articles, preserve their schema and inspect the current Studio implementation before adding or renaming fields. The repository contains articles from more than one metadata generation, so do not normalize unrelated frontmatter during a focused edit.

## Content changes

- Search existing articles by identifier, title, and synonyms before creating a concept.
- Prefer the verified SNOMED CT concept supplied by ThaiOML Studio or the backend lookup. Never invent a concept ID.
- Keep filenames human-readable and kebab-case.
- Follow the author guideline's high-yield structure, language, Thai-priority, and licensing rules.
- Use original or properly licensed visuals and never include identifiable patient data without documented authority.

## Editorial metadata

- Keep `review_status` consistent with the actual workflow stage. Do not advance review or publication status without the required human decision.
- Preserve `assigned_editor`, `assigned_reviewers`, `active_author`, and review dates when present unless the task explicitly changes them.
- Use string values for terminology identifiers to avoid numeric coercion.
- New drafts follow the frontmatter generated by ThaiOML Studio. Existing published articles may use `id`, while current Studio drafts use `snomed_id`; inspect consumers before migrating either key.

## Terminology links

Use the format supported by the current editor, backend, and `webapp/src/lib/remark-thaioml-linker.ts`. Linking conventions are implementation-dependent; do not declare an existing format obsolete or rewrite links globally without verifying every consumer.

After editing, validate the frontmatter parses, the article renders, terminology targets resolve or fall back as designed, and the status matches the editorial action taken.
